# Контракты MVP

Модульный монолит FastAPI и отдельный воркер. PostgreSQL через SQLAlchemy/Alembic хранит задания, результаты, подписку и состояние очереди. Redis Lists через redis-py сигнализирует воркеру о новых ID; периодический поиск в БД восстанавливает потерянные сигналы и просроченные аренды. Исходники и производные страницы лежат в закрытом S3-бакете через boto3. API проверяет владельца перед чтением. Для локальных тестов возможны SQLite и тестовые адаптеры очереди и хранилища.

## Границы

- Агент AI: app/ai/, Gemini, Fake, формальная проверка и контракт Pydantic.
- Агент backend: app/db.py, app/accounts.py, app/billing.py, миграции и модели аккаунтов/подписок/лимитов.
- Агент tests: tests/, пользовательские сценарии и интеграция.
- Координатор: app/main.py, app/config.py, app/core.py, app/submissions.py, app/work.py, app/files.py, app/storage.py, контейнеры, README и интеграция.

## Интерфейсы

AIProvider.recognize(pages: list[PageInput], clarification: str | None) -> list[RecognizedTask]; AIProvider.review(tasks: list[RecognizedTask], clarification: str | None) -> list[PreliminaryReview]. PageInput(number: int, content: bytes, mime_type: str). Порядок выводов соответствует входным заданиям. RecognizedTask содержит page_number (от 1), number, condition, answer, answer_state (present, blank, unreadable, unknown), kind, optional region. PreliminaryReview содержит status, explanation, expected_answer, uncertainty, missing_data. Метаданные провайдера provider.name и provider.demonstration. AIError(code, retryable). Статусы correct, incorrect, partially_correct, needs_review, no_answer, unreadable. Формальная проверка ограничена однозначными арифметикой, сравнением чисел и документированными единицами.

PaymentProvider.checkout(CheckoutIntent) получает сохранённый снимок тарифа и возвращает ссылку оформления. PaymentProvider.cancel(external_subscription_id) отменяет продление. PaymentProvider.parse_event(raw_body, headers) проверяет уведомление и нормализует событие. FakePaymentProvider принимает подписанные тестовые события, использует отдельный секрет и обозначает тестовые операции. Статусы подписки inactive, active, past_due, expired. Отмена хранится отдельным флагом и сохраняет доступ до конца оплаченного периода. Повторы событий уникальны по ID; запоздалые переходы сверяются с версией события. Статусы работ/задач queued, processing, completed, failed. Этапы без процентов.

## Запись и лимиты

Создание работы, запись задачи и резерв проверки в одной транзакции; публикация ID после commit. Воркеры захватывают аренду задачи атомарно, выполняют IO вне транзакции и публикуют результат только при действующей аренде. Окончательный успех переводит резерв в использование, окончательный сбой возвращает его; повторная доставка и повторные попытки используют прежний ID. Уточнение, добавление страниц и повторная проверка ранее оплаченной работы не создают нового списания. Повтор первой неуспешной обработки резервирует заново в текущем периоде. История успешного использования сохраняется после удаления работы. Тариф ограничивает общее число страниц и доступ к уточнениям. Принято допущение: общий кластер с изоляцией по владельцу, небольшая пилотная нагрузка, чувствительные учебные данные, доступ в локальной среде. Цели SLA и прогноз нагрузки до пилота требуют измерения.

## Веб-интерфейс

`site/serve.js` раздаёт статические файлы и передаёт только `/v1` настроенному FastAPI. `site/api.js` централизует запросы, Bearer-сессию и ошибки. `site/app.js` управляет экранами макета, загрузкой, статусом работы и карточками заданий. `site/billing.js` загружает подписку и тарифы, проводит тестовое оформление через существующие маршруты и обновляет отображение остатка. Файлы передаются как FormData с полем `files`. Защищённая страница читается как Blob по авторизованному запросу. Серверный статус определяет момент окончания опроса, при смене экрана текущий запрос отменяется.
