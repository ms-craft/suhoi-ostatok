# Сухой остаток

Бэкенд для предварительной проверки школьных работ. Учителю достаточно загрузить фотографии или PDF. Предмет, задания, ответы и критерии заранее вводить не требуется. После обработки можно посмотреть страницу, исправить распознавание и вывод, добавить материалы, перепроверить задание и подтвердить итог.

## Запуск

### Сайт и API

Исходный макет находится в папке `site/`. Сайт работает на HTML, CSS и JavaScript. Запустите бэкенд по инструкции ниже, затем в отдельном терминале из корня проекта запустите локальный сервер сайта. Нужен Node.js, установка npm-пакетов для сайта не требуется.

```powershell
node site/serve.js
```

Откройте [Сухой остаток](http://127.0.0.1:5173). Сервер сайта передаёт запросы `/v1` на FastAPI по тому же адресу, который видит браузер. По умолчанию FastAPI доступен прокси на `http://127.0.0.1:8000`. Чтобы изменить адрес API или порт сайта, задайте `API_ORIGIN` или `SITE_PORT` перед запуском.

```powershell
$env:API_ORIGIN = 'http://127.0.0.1:8000'
$env:SITE_PORT = '5173'
node site/serve.js
```

1. Нажмите **Зарегистрироваться** или **Войти**. Для нового аккаунта укажите адрес электронной почты и пароль от 12 символов.
2. Откройте **Подписка**, выберите демонстрационный тариф и подтвердите тестовое оформление. Остаток проверок появится в подписке. Отмена продления сохраняет доступ до конца уже оформленного периода.
3. Загрузите синтетический JPEG, PNG, HEIC, HEIF или PDF. Несколько фотографий в одной загрузке должны быть страницами работы одного ученика. После завершения откройте результат, исправьте или подтвердите задание. Удалить работу можно из её карточки.

Для проверки через сайт оставьте `AI_PROVIDER=fake` в `.env`. Результат помечен как демонстрационный и построен из вымышленных заданий. Тестовое оформление использует `FakePaymentProvider`. Значения `FAKE_PAYMENT_SECRET` и `GEMINI_API_KEY` задаются только на стороне API и воркера.

В настройках работы можно ввести предмет или выбрать подсказку из справочника. Для собственного названия нужно указать тип предмета. При использовании Gemini распознавание листов по математике и естественным наукам выполняет `GEMINI_RECOGNITION_MODEL`, а по гуманитарным предметам — `GEMINI_HUMANITIES_MODEL`. Если предмет не выбран, используется `GEMINI_RECOGNITION_MODEL`. Предмет и задания сохраняются в снимке при загрузке листа; изменения шаблона применяются к следующим загрузкам.

Токен хранится в `sessionStorage` вкладки. Перезагрузка страницы сохраняет вход в этой вкладке, выход очищает локальную сессию. Уже выданный токен действителен на сервере до истечения срока. Токен доступен JavaScript того же источника, поэтому для внешнего пилота нужны HTTPS и контроль сторонних скриптов. Изображения загружаются с заголовком Authorization и отображаются через временные Blob URL.

Превью из исходного архива лежат в `site/preview/`. Страницы рабочего сайта получают список, статусы и результаты из API. Файлы демонстрационного макета сохранены как справочный материал.

### Бэкенд через Docker Compose

Нужны Docker Engine с Linux-контейнерами и Docker Compose v2. В корне проекта скопируйте настройки для локального запуска и поднимите сервисы.

```bash
cp .env.example .env
docker compose up --build -d
docker compose ps -a
curl -fsS http://127.0.0.1:8000/health/ready
```

В PowerShell выполните `Copy-Item .env.example .env` и используйте `curl.exe`. API публикуется только на loopback. Compose запускает миграцию и создаёт приватный S3-бакет перед стартом API и воркера. [Swagger UI](http://127.0.0.1:8000/docs).

```bash
docker compose run --rm migrate alembic upgrade head
docker compose run --rm migrate alembic check
docker compose logs -f api worker
docker compose stop
```

Тесты через Compose или локально с Python 3.12.

```bash
docker compose --profile test run --build --rm test

python -m venv .venv
# Активируйте venv. В PowerShell используйте .\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

По умолчанию тесты используют временные SQLite-файлы, память для хранения и сигналов очереди, Fake-провайдеры и имитацию HTTP-ответов Gemini. Для дополнительного конкурентного теста задайте `TEST_DATABASE_URL=postgresql+psycopg://...` на отдельной тестовой БД. Тест создаёт и удаляет изолированную схему.

Для браузерного теста с синтетическими данными запустите в отдельных терминалах команды ниже. Первый процесс запускает тот же FastAPI и обработчик фоновых задач с временной SQLite и хранилищем в памяти. Тестовая конфигурация даёт две проверки и включает сценарий с пустым результатом.

```powershell
# Терминал 1, в активном Python venv
python -m tests.browser.fixture_backend

# Терминал 2
$env:API_ORIGIN = 'http://127.0.0.1:58100'
node site/serve.js

# Терминал 3, с доступным Playwright и Chromium
node tests/browser/smoke.mjs
```

При необходимости задайте `PLAYWRIGHT_MODULE` как путь к пакету Playwright, а `BROWSER_BIN` как путь к установленному Chromium, Chrome или Edge. По умолчанию скрипт открывает сайт на порту 5173. Для другого адреса задайте `SITE_URL`.

## Архитектура

FastAPI принимает запросы, SQLAlchemy и Alembic управляют схемой PostgreSQL. PostgreSQL хранит аккаунты, задания воркера, распознавание, версии результатов, действия учителя, подписку и журнал использования. [Контракты и границы модулей](ARCHITECTURE.md).

Воркер работает отдельным процессом из того же образа. Библиотека **redis-py** использует очередь Redis Lists (`LPUSH`, `BRPOP`) с одним типом сообщения — ID задачи. Статус задачи и время следующей попытки хранятся в PostgreSQL. Периодический поиск в БД восстанавливает обработку после потери Redis-сигнала. Воркер захватывает аренду задания в транзакции, продлевает её во время обработки и публикует результат только при действующей аренде. Повторное сообщение не создаёт второго результата или списания. Сбой после внешнего вызова может привести к повторному вызову ИИ при восстановлении аренды.

Библиотека **boto3** использует стандартный S3 API и позволяет задать endpoint. Локальный Compose использует RustFS с закрытым бакетом. Объекты получают случайные ключи, а выдача файлов идёт через API после проверки владельца. [Документация контейнера RustFS](https://docs.rustfs.com/en/installation/container).

## Загрузка, ИИ и участие учителя

- Принимаются статические JPEG и PNG либо один PDF на запрос. В одной работе может быть несколько изображений или страницы одного PDF. Дополнение — отдельная загрузка. Пределы по умолчанию составляют 12 МиБ на файл, 32 МиБ на HTTP-запрос, 10 страниц на работу и 20 млн пикселей на исходную фотографию. Тариф может снижать предел страниц.
- Сервис сверяет сигнатуру и MIME, декодирует JPEG, PNG, HEIC/HEIF или PDF, отклоняет повреждённые, защищённые паролем и неподдерживаемые файлы. Оригиналы сохраняются побайтно. PDFium выводит страницы в порядке документа. Pillow нормализует ориентацию фотографий и сохраняет JPEG до 2 000 пикселей по длинной стороне. Для каждой найденной записи доступна страница с ответом. Область ответа поддерживается в модели данных как нормализованный прямоугольник, Gemini возвращает ссылку на страницу до проверки точности локализации.
- `FakeAIProvider` подставляет вымышленные демонстрационные данные для каждой страницы и помечает их `demonstration: true`. Пометка остаётся у карточки с демонстрационной историей после смены провайдера. `GeminiAIProvider` использует `gemini-3.8-flash`, стабильную мультимодальную модель с поддержкой изображений, документов и структурированного вывода. Смена провайдера или модели применяется после пересоздания API и воркера. [Gemini 3.8 Flash](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash?authuser=993749347) · [Структурированный вывод GenerateContent](https://ai.google.dev/gemini-api/docs/generate-content/structured-output).
- Gemini получает нормализованные JPEG и текстовые уточнения учителя на этапе распознавания. Изображения отправляются блоками до восьми страниц или 12 МиБ до Base64. На этапе проверки передаются распознанные задания, ответы, применимые исправления и уточнения для случаев, где требуется вывод модели. Однозначные случаи и защитные правила обрабатываются локально. Отдельные метаданные аккаунта, токены и исходные файлы в запрос не включаются. Сама работа может содержать персональные данные. Условия на разных блоках могут потребовать уточнения учителем.
- Сервер валидирует структурированные ответы Pydantic, сверяет номера страниц и число результатов. Изображения и текст считаются недоверенными данными. Модели не предоставляются инструменты или доступ к базе и хранилищу. Сервис не выставляет окончательную оценку автоматически.
- Формальная проверка на `Decimal` поддерживает целые числа и десятичные дроби с точкой или запятой, простые сравнения, скобки, унарные знаки и операции сложения, вычитания, умножения и деления. Поддерживаются длина (мм, см, дм, м, км), масса (мг, г, кг, т) и время (с, мин, ч) с латинскими эквивалентами. Сравнение и перевод выполняются внутри одной размерности. Периодические дроби, произвольные правила округления, степени, составные единицы и свободная формулировка выходят за рамки формального парсера. Ввод обрабатывается ограниченной грамматикой.
- У задачи сохраняются исходное распознавание, первый предварительный вывод, следующие версии и отдельная история действий учителя. Добавление страницы запускает повторный анализ всей работы. Найденные задания сопоставляются по странице и однозначному номеру или по распознанному тексту, поэтому при неоднозначном совпадении может появиться дополнительная карточка. До четырёх последних текстовых уточнений общей длиной до 4 000 символов передаются следующей проверке. Отдельная перепроверка применяет правки к выбранному заданию. Правка или новая проверка могут снять прежнее подтверждение.
- `correct`, `incorrect` и `partially_correct` обозначают предварительную оценку. `needs_review` требуется при отсутствующем условии, неоднозначности, неизвестном типе или открытом задании. `unreadable` обозначает неразборчивую запись, `no_answer` — явно пустое поле. Пустой список `tasks` означает, что обработка завершилась без найденных заданий. Только действие учителя устанавливает `confirmed`.

Статусы фоновой обработки — `queued`, `processing`, `completed`, `failed`. API возвращает этап (`preparing_pages`, `recognition`, `preliminary_review`, `validation`, `saving_results` и другие), код и безопасное сообщение при ошибке. При временной ошибке задача возвращается в очередь с задержкой. После исчерпания попыток можно вручную отправить работу на повторную обработку.

## Подписка и лимиты

Демонстрационный тариф `demo` включает 10 проверок на период, до 10 страниц на работу и уточнения. Цена по умолчанию не установлена. Пример собственного тестового каталога для `.env`.

```dotenv
PLANS_JSON=[{"code":"demo","name":"Тестовый тариф","checks_limit":10,"max_pages":10,"allow_followups":true,"price_minor":null,"currency":null}]
```

- Сервер резервирует одну проверку в транзакции создания работы и первой задачи. Резерв сразу уменьшает доступный остаток. Блокировка на уровне учителя сериализует конкурентные резервы. Успех фиксирует расход, включая завершённый анализ с пустым списком заданий.
- Временная ошибка сохраняет резерв. Терминальная ошибка или удаление работы до завершения освобождает его. Ручной перезапуск до первого успеха берёт новый резерв текущего периода. Уточнение и повторная проверка ранее успешно обработанной работы не списывают ещё одну проверку. Для них нужен действующий тариф с `allow_followups`. Удаление успешно обработанной работы сохраняет историю расхода.
- Проверенное платёжное событие открывает новый период со снимком лимитов тарифа. Досрочное продление сохраняет прежний остаток до начала нового периода. Отмена продления сохраняет уже оплаченный период. При ошибке платежа отображается `past_due`, доступ по уже оплаченному периоду сохраняется до его окончания.
- Тестовое оформление возвращает `checkout_url`. Подтверждение имитирует подписанное событие и даёт тестовый период на 30 дней. Реальные платежи и данные карт отсутствуют. Для имитации продления, отмены или ошибки отправьте подписанное уведомление с типом `renewed`, `cancelled` или `payment_failed`. Для открытия периода используйте `payment_succeeded`.
- Уведомление содержит `id`, `checkout_id`, `type`, монотонный `sequence` и для оплаты или продления — `period_start`, `period_end` в ISO 8601 с часовым поясом. Заголовок `X-Payment-Signature` — HMAC SHA-256 в hex от необработанного тела с `FAKE_PAYMENT_SECRET`. Повторный ID идемпотентен. Устаревшие версии и события заменённого оформления не переписывают действующую подписку.
- Реальная интеграция требует выбора страны и провайдера. Реализуйте `PaymentProvider` для размещённого у провайдера checkout, отмены и верификации webhook. Сверяйте версии и оплаченные периоды с API провайдера при задержанных и частичных событиях. Активируйте доступ по подтверждённому событию, сохраняйте внешние идентификаторы и настройте ограничение доступа к платёжным секретам.

## REST API

Все маршруты работ и подписки используют `Authorization: Bearer <access_token>`. Тарифы и проверка доступности публичны. Webhook аутентифицируется подписью. Единый формат ошибки API — `{"error":{"code":"...","message":"...","request_id":"..."}}`. Ответ также содержит `X-Request-ID`. Для чужих ресурсов возвращается 404, для исчерпанного лимита 429, для превышения размера или числа страниц 413.

| Метод и путь | Назначение |
| --- | --- |
| `POST /v1/auth/register`, `POST /v1/auth/login` | Получить Bearer-токен. |
| `GET /v1/plans`, `GET /v1/subscription` | Список тарифов, статус подписки, оплаченный период и остаток. |
| `POST /v1/subscription/checkout`, `POST /v1/subscription/cancel` | Начать оформление и отменить продление. |
| `GET /v1/payments/fake/checkout/{id}`, `POST /v1/payments/fake/checkout/{id}/confirm` | Просмотреть и подтвердить тестовое оформление. |
| `POST /v1/payments/webhook` | Принять подписанное уведомление. |
| `POST /v1/submissions`, `GET /v1/submissions` | Загрузить работу (multipart, поле `files`) и получить список (параметры limit и offset). |
| `GET /v1/submissions/{id}`, `GET /v1/submissions/{id}/jobs/{job_id}` | Статус работы и отдельной фоновой задачи. |
| `PATCH /v1/submissions/{id}` | Добавить или удалить необязательную метку ученика `student_reference`. API хранит её отдельно от материалов для ИИ. |
| `GET /v1/submissions/{id}/results` | Результаты, происхождение и подтверждения. |
| `GET /v1/submissions/{id}/pages/{number}`, `GET /v1/submissions/{id}/files/{number}` | Получить страницу JPEG или скачать исходный файл. Нумерация с 1. |
| `POST /v1/submissions/{id}/clarifications` | Добавить `text` и/или `files` в multipart-запросе. |
| `POST /v1/submissions/{id}/retry` | Запустить заново задачу с терминальной ошибкой. |
| `PATCH /v1/submissions/{id}/tasks/{task_id}` | Исправить `condition`, `answer`, `status` и/или `explanation`. |
| `POST /v1/submissions/{id}/tasks/{task_id}/recheck` | Перепроверить конкретное задание с правками. |
| `POST /v1/submissions/{id}/tasks/{task_id}/confirm` | Подтвердить итог выбранного задания. |
| `DELETE /v1/submissions/{id}` | Удалить работу и все связанные объекты. |

### Сквозной пример с тестовыми провайдерами

Нужны Bash, curl, jq и любой синтетический файл `example.jpg`. Подставьте уникальный адрес для первой регистрации.

```bash
set -euo pipefail
base=http://127.0.0.1:8000/v1
credentials='{"email":"teacher@example.invalid","password":"local-demo-passphrase"}'
curl -fsS "$base/auth/register" -H 'Content-Type: application/json' -d "$credentials" > /dev/null
token=$(curl -fsS "$base/auth/login" -H 'Content-Type: application/json' -d "$credentials" | jq -r .access_token)
auth="Authorization: Bearer $token"

curl -fsS "$base/plans"
checkout=$(curl -fsS "$base/subscription/checkout" -H "$auth" -H 'Content-Type: application/json' -d '{"plan_code":"demo"}' | jq -r .checkout_id)
curl -fsS -X POST "$base/payments/fake/checkout/$checkout/confirm" -H "$auth"
curl -fsS "$base/subscription" -H "$auth"

work=$(curl -fsS "$base/submissions" -H "$auth" -F 'files=@example.jpg;type=image/jpeg' | jq -r .id)
work_url="$base/submissions/$work"

wait_for_work() {
  for ((i=0; i<45; i++)); do
    data=$(curl -fsS "$work_url" -H "$auth")
    case $(jq -r .status <<< "$data") in
      completed) return 0 ;;
      failed) jq '{stage,error_code,error_message}' <<< "$data"; return 1 ;;
    esac
    sleep 1
  done
  echo 'Истекло время ожидания задачи.' >&2
  return 1
}

wait_for_work
results=$(curl -fsS "$work_url/results" -H "$auth")
jq . <<< "$results"
task=$(jq -r '.tasks[0].id' <<< "$results")
task_url="$work_url/tasks/$task"
curl -fsS -X PATCH "$task_url" -H "$auth" -H 'Content-Type: application/json' -d '{"answer":"4"}'
curl -fsS -X POST "$task_url/recheck" -H "$auth"
wait_for_work
curl -fsS -X POST "$task_url/confirm" -H "$auth"
curl -fsS "$base/subscription" -H "$auth"
curl -fsS -X DELETE "$work_url" -H "$auth"
```

## Логи, хранение и пилот

API и воркер выводят JSON в stdout. События связываются через `request_id`, `job_id` и `submission_id`. Записываются этап, попытка, длительность, технический код, модель и доступные счётчики токенов. Пароли, токены, подписи, платёжные реквизиты, содержимое работ и полные обращения к ИИ исключены из прикладных логов. `GET /health/live` проверяет доступность процесса, `GET /health/ready` проверяет наличие схемы и соединение с PostgreSQL, Redis и бакетом. Для Sentry или другого сборщика подключайте оба процесса, передавайте технические идентификаторы и отключайте отправку тел запросов, переменных окружения, заголовков и локальных переменных с данными работ.

Удаление сразу скрывает работу и затем удаляет оригиналы и производные страницы, связанные задачи, результаты и историю правок. При сбое S3 воркер повторяет удаление. При жёстком завершении API между записью объекта и коммитом БД или при потере ответа БД на коммит может остаться непривязанный объект. Для пилота настройте сверку бакета с БД, очистку непривязанных объектов с защитным интервалом и отдельную политику версий и резервных копий. Учёт уже использованной проверки сохраняется.

Учитель входит по паролю с Argon2id. Токен имеет срок действия, в БД хранится только его хеш. Локальная схема допускает открытую регистрацию. Перед внешним пилотом настройте ограничение запросов, TLS, управление аккаунтами, ротацию секретов, доступы БД и S3, резервное копирование и изоляцию процесса рендеринга для недоверенных PDF. Измерьте задержки и качество распознавания на обезличенном наборе с разными предметами, почерками и качеством снимков.

До обработки реальных работ детей проверьте правовые основания, условия ИИ-провайдера и доступность в стране пилота, расположение данных, сроки хранения и порядок удаления. Настройте процессы для удаления данных у всех привлечённых провайдеров. Требования законодательства и пригодность ИИ для оценивания требуют отдельной проверки.
