# Запуск «Сухого остатка» на Windows

Эта инструкция предназначена для локального запуска на одном компьютере. Сайт открывается на `127.0.0.1` и по умолчанию недоступен с других устройств.

## Вариант 1. Запуск уже настроенной папки на этом компьютере

Если у вас осталась папка `C:\Users\User\Desktop\stopkadr` вместе с `.local-run`, `.venv` и `.env`, запустите PowerShell и выполните:

```powershell
cd C:\Users\User\Desktop\stopkadr
pwsh -NoProfile -ExecutionPolicy Bypass -File .local-run/start.ps1
```

После появления адреса откройте [http://127.0.0.1:5173](http://127.0.0.1:5173). Скрипт запускает сайт, API, обработчик, базу и хранилище. Настройки ИИ он берёт из `.env`.

Если сайт уже открыт и работает, повторно запускать команду не нужно. Для перезапуска сначала остановите сервисы следующей командой, затем снова запустите `start.ps1`.

Остановить сервисы:

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .local-run/start.ps1 -Stop
```

Эта команда рассчитана на уже подготовленные файлы и пути именно этого компьютера. `.local-run` и `.env` не хранятся в GitHub, поэтому после нового скачивания репозитория используйте вариант 2.

Для запуска на этом настроенном компьютере **вместе с доступом с телефона** можно использовать одну команду:

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File C:\Users\User\Desktop\stopkadr\scripts\start-phone.ps1
```

Скрипт выведет адрес для телефона и при необходимости попросит права администратора для правила брандмауэра, ограниченного локальной подсетью. Телефон и компьютер должны быть в одной доверенной сети Wi-Fi. Адрес использует HTTP без шифрования; для реальных данных нужен HTTPS. Для остановки добавьте `-Stop` в конец той же команды. Этот вариант зависит от локальной установки из варианта 1; на другой компьютер `.local-run` автоматически из GitHub не переносится.

## Вариант 2. Новая установка с GitHub через Docker

### 1. Установите программы

1. Установите [Git для Windows](https://git-scm.com/install/windows).
2. Установите [Docker Desktop для Windows](https://docs.docker.com/desktop/setup/install/windows-install/) и настройте WSL 2 по его инструкции. Запустите Docker Desktop и дождитесь готовности Linux-контейнеров. Node.js отдельно устанавливать не нужно: сайт запускается в контейнере.

Закройте и заново откройте PowerShell, затем проверьте:

```powershell
git --version
docker --version
docker compose version
```

Если команда не найдена, убедитесь, что программа установлена, и откройте новое окно PowerShell.

### 2. Скачайте проект

Для новой папки на рабочем столе:

```powershell
cd $env:USERPROFILE\Desktop
git clone https://github.com/ms-craft/suhoi-ostatok.git suhoi-ostatok
cd suhoi-ostatok
```

Если папка проекта уже существует, перейдите в неё через `cd` вместо повторного `git clone`. При скачивании с GitHub вы получаете последнюю отправленную версию ветки `main`; ещё не отправленные изменения из другой локальной папки туда не попадут.

### 3. Настройте окружение

Создайте `.env` из примера **только если его ещё нет**, чтобы не перезаписать свои настройки:

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
```

Для запуска без реальных обращений к ИИ укажите `AI_PROVIDER=fake`. Это демонстрационный режим с вымышленными результатами.

Для работы с вашим ключом AIAI найдите строки настроек ИИ и задайте:

```dotenv
AI_PROVIDER=gemini
GEMINI_API_BASE=https://api.aiai.by/v1
GEMINI_API_KEY=ВАШ_НОВЫЙ_КЛЮЧ
GEMINI_MODEL=gemini-3.8-flash
GEMINI_RECOGNITION_MODEL=gemini-3.5-flash-lite
GEMINI_HUMANITIES_MODEL=gemini-3.8-flash
```

Уберите `#` в начале строк, если он есть, и убедитесь, что каждая настройка встречается только один раз. Подставьте свой действующий ключ, не публикуйте `.env` и не отправляйте ключ в переписке. Если ключ уже был раскрыт, перевыпустите его у провайдера.

### 4. Запустите API и обработчик

В PowerShell из корня проекта:

```powershell
docker compose up --build -d
docker compose ps -a
curl.exe -f http://127.0.0.1:8000/health/ready
```

При первом запуске Docker скачает образы и установит зависимости. Это может занять несколько минут. Миграции базы и подготовка хранилища выполняются при запуске. Сервисы `migrate`, `bucket` и `s3-permissions` могут завершиться успешно: они выполняют одноразовую подготовку.

### 5. Откройте сайт

Сайт уже запущен командой Docker Compose. Откройте [http://127.0.0.1:5173](http://127.0.0.1:5173). Зарегистрируйте аккаунт учителя: новому аккаунту выдаются 30 бесплатных листов. Создайте класс и работу, затем загрузите лист. Оплата в этой локальной конфигурации демонстрационная и не списывает деньги; обращения к реальному ИИ-провайдеру могут быть платными.

В режиме `fake` результаты вымышленные. В режиме Gemini выбранный предмет определяет модель распознавания; отправленные фотографии передаются настроенному ИИ-провайдеру.

## Следующий запуск и остановка

1. Запустите Docker Desktop.
2. В PowerShell перейдите в папку проекта и выполните `docker compose up -d`.
3. Откройте [http://127.0.0.1:5173](http://127.0.0.1:5173).

Чтобы обновить ранее скачанную копию после изменений в GitHub, выполните `git pull origin main` и `docker compose up -d --build`. Если в копии есть собственные незакоммиченные изменения, сначала сохраните их: Git может не разрешить обновление поверх них.

Для Telegram настройте отдельный `TELEGRAM_BOT_TOKEN` в `.env` и вместо обычного запуска Docker используйте `docker compose --profile telegram up -d --build`. Один и тот же токен нельзя одновременно использовать в двух запущенных копиях бота: они будут конкурировать за сообщения. Подробнее — [инструкция по Telegram](TELEGRAM.md).

Чтобы остановить сайт и серверные сервисы, выполните в корне проекта:

```powershell
docker compose stop
```

Эта команда сохраняет Docker-тома с базой и файлами. Не используйте `docker compose down -v`, если нужны сохранённые данные: ключ `-v` удаляет тома проекта.

## Если что-то не запускается

- **Порты заняты.** Уже запущенный вариант 1 и Docker-вариант используют одни и те же порты 8000 и 5173. Сначала остановите прежний запуск. Данные варианта 1 и Docker хранятся отдельно и автоматически не переносятся.
- **Ошибка подключения к Docker.** Откройте Docker Desktop и дождитесь его запуска. Проверьте `docker compose ps -a` и `docker compose logs api worker`.
- **Сайт открылся, но не выполняет проверку.** Убедитесь, что API отвечает на `/health/ready`, а в подписке есть проверки. Для реального ИИ проверьте `AI_PROVIDER`, адрес, ключ и доступность провайдера. После изменения `.env` пересоздайте сервисы командой `docker compose up -d`.
- **Фотография не загружается.** Проверьте формат и действующие настройки размера файла и разрешения в `.env`. После изменения настроек пересоздайте сервисы. Слишком большое исходное изображение может быть отклонено до уменьшения.
- **Не открывается сайт.** Проверьте `docker compose ps -a` и убедитесь, что контейнер `site` запущен.

Классы и шаблоны работ синхронизируются с сервером и доступны при входе в тот же аккаунт с другого устройства. Отдельная установка на компьютере друга использует собственные базу и хранилище: ваши аккаунты, листы и результаты в неё автоматически не копируются.
