# Проверка интеграции Gemini

Адаптер по умолчанию использует `gemini-3.8-flash`. Он отправляет запросы `generateContent` по HTTPS, передаёт ключ в заголовке `x-goog-api-key` и запрашивает JSON через `generationConfig.responseFormat.text`. Сетевая схема ограничена поддерживаемым Google подмножеством JSON Schema. Ответ дополнительно проверяется локальными ограничениями Pydantic и правилами сервиса. Перед пилотом подтвердите доступность выбранной модели и её квоты в проекте Google. [Описание модели](https://ai.google.dev/gemini-api/docs/latest-model) · [REST API](https://ai.google.dev/api/generate-content) · [Структурированный ответ](https://ai.google.dev/gemini-api/docs/generate-content/structured-output).

- Распознавание отправляет нормализованные JPEG-страницы с номерами и, если они есть, текст уточнений учителя. Пакет ограничен восемью страницами и 12 МиБ исходных JPEG. После Base64 остаётся запас до документированного предела inline-запроса в 20 МБ. [Изображения в GenerateContent](https://ai.google.dev/gemini-api/docs/generate-content/image-understanding).
- Проверка вначале применяет локальные правила. Если результат уже определён, например простая арифметика или явно пустой ответ, повторный запрос Gemini не требуется. Для остальных заданий передаются транскрипция, применённые правки и уточнения, группами до 20 заданий. При целевой перепроверке страницы повторно не отправляются. Итог подтверждает учитель.
- Сетевой сбой и HTTP 408, 429, 5xx допускают повтор на уровне воркера с ограниченным числом попыток и экспоненциальной задержкой. Настроены 5 секунд на подключение и 45 секунд на остальные фазы HTTP. Ошибки доступа и формата, блокировка содержимого и неоконченный ответ дают безопасный код сбоя. Полный ответ и текст работ в служебные логи не выводятся. [Ошибки GenerateContent](https://ai.google.dev/gemini-api/docs/generate-content/api-errors).

## Синтетическая оценка

Запустите команды из корня репозитория с активным Python-окружением проекта.

```powershell
python -m scripts.ai.evaluate
```

По умолчанию оценка подаёт эталонные транскрипции напрямую в локальную проверку. Это проверяет правила и сохранение статуса `needs_review` для открытого ответа. Метрики распознавания доступны в отдельном живом прогоне.

Для живой проверки задайте `GEMINI_API_KEY` в окружении процесса через хранилище секретов. При необходимости задайте `GEMINI_MODEL`. Выберите проект Google с разрешённой сетью и квотой, затем явно запустите обращение к API.

```powershell
python -m scripts.ai.evaluate --provider gemini
python -m scripts.ai.evaluate --provider gemini --case two-pages
```

Скрипт сам создаёт синтетические изображения в памяти. В наборе две страницы с арифметикой, сравнением и переводом единиц, открытый и незаполненный ответы, слегка повёрнутый и размытый лист, пустая страница. Параметра для пользовательских файлов нет. Ключ, распознанные тексты и ответы модели в отчёт не попадают.

Отчёт считает найденные, пропущенные и лишние задания. Сопоставление идёт по странице и номеру задания. Для совпавших заданий отдельно считаются точные совпадения условия, ответа с его состоянием и статуса по эталонам. Сравнение текста допускает нормализацию Unicode, регистра и пробелов. Ненулевой код выхода означает ошибку API или расхождение с эталоном. Отдельно отмечайте смысловые совпадения при ручной проверке. Этот небольшой набор предназначен для проверки интеграции. До допуска пилота согласуйте с учителями отдельный набор учебных сценариев, пороги ошибок и правила обработки случаев `needs_review`.
