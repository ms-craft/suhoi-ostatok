# Доступ и данные пилота

## Допуск учителей

В локальном режиме регистрация открыта. Для закрытого пилота оператор задаёт адреса приглашённых в `PILOT_ALLOWED_EMAILS` и создаёт отдельный случайный `PILOT_ACCESS_CODE`. Список адресов и код хранятся только на сервере. Учитель указывает свой адрес, пароль и код при регистрации. Для дальнейшего входа используются адрес и пароль. Исключение адреса из списка и перезапуск API закрывают доступ по ранее выданным токенам. При повторном добавлении адреса ещё действующий токен снова получит доступ, поэтому для постоянного отзыва оператору нужно также удалить токены пользователя из БД.

Пилотный API ограничивает вход и регистрацию для каждого разрешённого адреса восемью попытками за минуту на операцию. Лимит общий для реплик и хранится в Redis под хешированным ключом. При недоступности Redis вход и регистрация возвращают временную ошибку. TLS-прокси дополнительно ограничивает запросы по IP и открывает доступ только из разрешённой сети. Код приглашения общий для пилота, поэтому передавайте его отдельно от публичной ссылки. Адрес вводится пользователем и не подтверждается по почте. Ведите список выданных приглашений и меняйте код при подозрении на утечку. [Конфигурация эксплуатации](OPERATIONS.md).

## Поток данных

| Этап | Какие данные обрабатываются |
| --- | --- |
| Учётная запись | Email и хеш Argon2id в PostgreSQL. Токен передаётся в HTTPS-заголовке и хранится в БД как хеш с датой истечения. |
| Загрузка | JPEG, PNG или PDF поступают в API. Сервер проверяет сигнатуру, MIME, размер, лимит страниц и пикселей. Оригинал и нормализованные JPEG находятся в закрытом S3-бакете. |
| Анализ | В PostgreSQL хранятся данные работы, распознанные задания и ответы, история исправлений, ссылки на объекты и задания воркера. Redis переносит идентификаторы задач и счётчики входа. |
| Gemini | Если оператор разрешил Gemini, Google получает нормализованные JPEG и при наличии уточнение учителя. Для заданий, требующих ответа модели, в запрос проверки входят распознанный текст, релевантные исправления и уточнение. Отдельная метка ученика и реквизиты аккаунта в запросы не включаются. Сами листы и текст могут содержать персональные данные. [Режимы и проверка Gemini](GEMINI.md). |
| Оплата | FakePaymentProvider в пилоте хранит события тестового оформления и сведения о подписке. Банковские реквизиты через этот поток не проходят. |

В пилоте PDF обрабатывает отдельный краткоживущий процесс без переменных окружения приложения. На каждый процесс API допускается один активный рендер, с ограничением в 25 секунд и выходом до 64 МиБ. В Linux ограничены CPU и адресное пространство. Это ограничивает последствия зависания или перерасхода ресурсов. Процесс по-прежнему работает в контейнере API с тем же пользователем и видит его файловую систему и сеть. Для обработки реальных недоверенных PDF нужна проверенная дополнительная изоляция рендера без доступа к секретам и сети.

## Удаление и сверка S3

Запрос на удаление сразу закрывает доступ к работе. Фоновая очистка удаляет оригиналы и страницы из S3 и связанные записи PostgreSQL. Если удаление S3 прерывается, воркер повторяет его. Политика резервных копий и версий S3 задаётся отдельно. Удаление объекта не гарантирует удаление его старых версий, копий из бэкапа или данных, отправленных внешнему провайдеру.

Сверка нужна, если S3 уже принял файл, а транзакция PostgreSQL не завершилась или подтверждение фиксации потерялось. Запустите команду в контейнере с настройками действующей БД и её выделенного бакета.

```sh
python -m app.orphans --grace-hours 48 --max-scan 5000
```

Режим по умолчанию выводит только счётчики и не удаляет объекты. Кандидат должен иметь ключ формата приложения, быть старше порога и отсутствовать в ссылках на оригиналы и страницы. Если достигнут предел сканирования, отчёт относится только к просмотренной части префикса. Перед удалением проверьте, что настройки указывают на одну пару БД и бакета, проверьте резервную копию и согласуйте окно обслуживания.

```sh
python -m app.orphans --apply --grace-hours 48 --max-scan 5000 --max-delete 100
```

Режим применения требует PostgreSQL и получает эксклюзивную advisory-блокировку. Загрузки текущей версии приложения берут совместную блокировку до первой записи в S3 и удерживают её до завершения транзакции. Если есть активная загрузка, команда прекращается до удаления. Перед удалением инструмент повторяет проверку объекта и ссылок, затем отправляет условный запрос с ETag. Используйте отдельный бакет или префикс, остановите старые версии загрузчиков и другие процессы записи. На выбранном S3-провайдере сначала проверьте условное удаление в отдельном синтетическом бакете. Операция требует список объектов префикса, HEAD и условный DELETE, старые версии объектов она не очищает.

## Решения владельца до работы с данными учеников

- Кто определяет цели и правила обработки данных, на каком основании работает пилот и требуется ли согласие школы или законных представителей?
- Какие материалы нужны для пилота, как обезличивать их до загрузки и кто вправе видеть оригиналы?
- В каких странах находятся БД, S3, копии и обработка Gemini? Допустимы ли условия выбранных провайдеров, их правила хранения и передачи?
- Какие сроки хранения действуют для оригиналов, результатов, событий, журналов, резервных копий и версий S3? Кто выполняет удаление и отвечает за обращения?
- Кто выдаёт и отзывает приглашения, проводит пробное восстановление и реагирует на инцидент?
